=== 2. SERVER: EXTRACTION (STAGE B) ===

2.1 SUBSCRIPTIONS AND THE GREP PROOF
 `grep -rn "WFCrackCompletedEvent\|WFCrackerFallingEvent" Content.Server Content.Shared Content.Client Content.IntegrationTests` (binaries excluded) returns four source hits: the declarations (WFCrackEvents.cs:11, :21), the raise sites (WFCrackerSystem.Crack.cs:230, :383) and the test recorder (GravityAnchorTest.cs:1196-1197). No production subscriber exists, so F5's two are the first.
 `WFPlanetChunkSystem.Initialize` declares exactly two subscriptions, both BROADCAST and both BY REF:
```
SubscribeLocalEvent<WFCrackCompletedEvent>(OnCrackCompleted);   // (ref WFCrackCompletedEvent args)
SubscribeLocalEvent<WFCrackerFallingEvent>(OnCrackerFalling);   // (ref WFCrackerFallingEvent args)
```
 F5 adds NO directed (component, event) subscription anywhere — not on WFPlanetCrackerComponent (WFCrackerSystem owns its MapInitEvent, WFCrackerSystem.cs:18), not on WFGravityAnchorComponent (WFGravityAnchorSystem owns all ten, :54-63), not on WFPlanetChunkComponent (the watchdog is a sweep), and explicitly NOT `TileChangedEvent` on CEZMapComponent, which CESharedZLevelsSystem.Movement.cs:24 already owns.

2.2 OnCrackCompleted — guards, in order
 1. `args.GroundMap` may be `EntityUid.Invalid` (Crack.cs:221 `?? EntityUid.Invalid`): bail with Log.Error.
 2. Resolve the cracker's WFPlanetCrackerComponent; if `Chunk` already resolves to a live chunk, bail.
 3. `IsPlanetCracked` -> bail with Log.Warning.
 4. Ground map must have MapGridComponent and BiomeComponent; the hull must resolve a berth centre (TryGetBerthCentre, SharedWFCrackerSystem.cs:18).
 Then `TryExtract(cracker, args.AnchorA, args.AnchorB, args.CentreXY, args.Radius, args.GroundMap, out var chunk)`.

2.3 TryExtract — the algorithm
 GEOMETRY. `radius = args.Radius`, `centre = args.CentreXY` verbatim (already the D21 value via TryGetCircle, SharedWFCrackerSystem.cs:61). `aabb = Box2.CenteredAround(centre, new Vector2(radius * 2f, radius * 2f))`. Ground layer is identity, so local == world.

 STEP 1 — FORCE THE TERRAIN TO EXIST. `_tileBuffer.Clear(); _biome.ReserveTiles(groundMap, aabb.Enlarged(1f), _tileBuffer, mapGrid: groundGrid);` The Clear is mandatory (ReserveTiles SetTiles the caller's list without clearing it, PlanetSetup.cs:105). NOT Preload (generates nothing, PlanetSetup.cs:152). Enlarged(1) so the rim ring and all four corner biome chunks are generated and pinned in the same pass. Reserve immediately before reading, in the same tick.

 STEP 2 — READ THE DISC AND BUILD _holeIndices. `_map.GetLocalTilesEnumerator(groundMap, groundGrid, aabb, ignoreEmpty: false)` (SharedMapSystem.Grid.cs:889); `ignoreEmpty: false` is mandatory. Per tile, radius-test the CENTRE: `((tileRef.GridIndices + groundGrid.TileSizeHalfVector) - centre).LengthSquared() <= radius * radius` (MapGridComponent.cs:63). Copy the WHOLE `tileRef.Tile` struct into `_chunkTiles` (Variant and RotationMirroring carry the biome's look; Tile.WithVariant drops RotationMirroring). Record each index in `_holeIndices` — [R2] this set is the ONE definition of "inside the circle" and steps 5, 7 and 8 all read it. Log.Warning with a count if any in-circle tile is still `IsEmpty` after step 1.

 STEP 3 — CREATE THE CHUNK ON THE GROUND MAP. `_mapManager.CreateGridEntity(groundMapId)`, then `_transform.SetWorldPositionRotation(chunk, groundGridWorldPos, groundGridWorldRot)` (GridFixtureSystem.cs:271 recipe) so tile indices are identical on both grids. Immediately `chunk.Comp.CanSplit = false` (E-J). MUST be created on the ground map and re-parented later: a grid created directly on the orbit map gets neither CEZPhysicsComponent nor CEZGridFallerComponent (GridAddEvent fires in nullspace, the pre-init AttachParent produces no MoveEvent, and SweepMapGridsForZPhysics at Transit.cs:67 has no callers).

 STEP 4 — ONE SetTiles ONTO THE CHUNK. `_map.SetTiles(chunk.Owner, chunk.Comp, _chunkTiles)` (SharedMapSystem.Grid.cs:839). Then `RemComp<GridAtmosphereComponent>(chunk.Owner)` (E-K).

 STEP 5 — MOVE THE ENTITIES, BEFORE emptying the source (GridFixtureSystem.cs:322-323). One query:
```
_moveSet.Clear();
_lookup.GetLocalEntitiesIntersecting(groundMap, new PhysShapeCircle(radius, centre), Transform.Empty, _moveSet, LookupFlags.Uncontained);
```
 (EntityLookupSystem.LocalQueries.cs:74; LookupFlags.Uncontained = Dynamic|Static|Sundries|Sensors, EntityLookupSystem.cs:57, so container contents ride with their container.) Per uid, in this order:
  - skip `uid == groundMap`, `uid == chunk.Owner`, `Transform(uid).ParentUid != groundMap`, and `HasComp<MapGridComponent>(uid)` (a landed transport is left behind deliberately — open risks).
  - [R2, E-L] compute `var idx = _map.TileIndicesFor(groundMap, groundGrid, xform.Coordinates);` FIRST and skip the uid when `!_holeIndices.Contains(idx)`. The lookup is a fixture-overlap query and is used only as a cheap prefilter; `_holeIndices` decides. This is what stops a rim-straddling mob riding up onto a tile that was never copied.
  - if it is a WFGravityAnchorComponent, `_anchors.BeginChunkRide(uid)` first (E-E).
  - ANCHORED: `_transform.Unanchor(uid, xform, setPhysics: false)` then `_transform.AnchorEntity((uid, xform), (chunk.Owner, chunk.Comp), idx)` — the cross-grid overload at SharedTransformSystem.Component.cs:73, which does NOT demand a matching GridUid (the convenience overload at :119 does and must not be used). [R2] `false` here means the destination tile is EMPTY (SharedMapSystem.Grid.cs:1290), which after the `_holeIndices` filter is unreachable: Log.Error naming the uid and the index and SKIP the entity, never SetParent it over vacuum.
  - UNANCHORED (players, mobs, items, crates): `_transform.SetParent(uid, xform, chunk.Owner)` (:773).
  - record `(uid, idx)` in `_moved` for step 6, and `_anchors.EndChunkRide(uid)` for anchors after both halves of the move.
  ReAnchor (:21) is internal and asserts a shared MapID, so unanchor/anchor is the only route.

 STEP 6 — TELL THE BIOME THE PROPS ARE GONE. For each moved uid: `_biome.WfForgetLoadedEntity((groundMap, biomeComp), uid, idx)` (§4.1). Without it the entries leak until the chunk next unloads and BiomeSystem.OnEntityTerminating can no longer find them (BiomeSystem.cs:114-120).

 STEP 7 [R2, SIMPLIFIED] — STAMP THE HOLE, ONE SetTiles. `_holeTiles` = every index in `_holeIndices` -> `Tile.Empty`; `_map.SetTiles(groundMap, groundGrid, _holeTiles)`. No rim tile is written (E-M): the rim indices keep whatever biome tile step 1 generated.

 STEP 8 — PIN THE HOLE AND THE RIM. `_biome.WfPinTiles((groundMap, biomeComp), _holeIndices)` and the rim indices (every index whose tile centre lies in `(radius, radius + 1f]`). ReserveTiles pinned most of them already but skips any tile whose layers produce nothing, and a fully emptied 16x16 map chunk is removed outright (SharedMapSystem.Grid.cs:702-711) after which GetTileRef fabricates Tile.Empty again — ModifiedTiles is then the only thing standing between the hole and a regenerated surface (BiomeSystem.ChunkLoader.cs:38-42, :81-95; the marker guard at MarkerProcessor.cs:281 rides on the same set), and the only thing that keeps the rim ring out of UnloadTiles (E-M).

 STEP 9 — RIM DECALS, AFTER the stamp. For each rim index, alternate `WFCrackRimStraight` / `WFCrackRimCurve` by tangent:
```
_decals.TryAddDecal(protoId, new EntityCoordinates(groundMap, idx), out var id, rotation: tangent, zIndex: 0, cleanable: false)
```
 Decal coordinates are the texture's BOTTOM-LEFT corner in the owning grid's local frame (Content.Shared/Decals/Decal.cs:11), so the index itself is correct for a tile-sized decal; rotation comes from the Angle argument, never from the sprite (DecalOverlay.cs:97 draws Frame0 only). [R2] `false` means the tile is space (DecalSystem.cs:315): count those and emit ONE aggregated Log.Warning, do not retry and do not stamp a tile to make room. Store every returned id in `chunk.Comp.RimDecals`. D19 keeps them for the round.

 STEP 10 — PUT THE CHUNK IN THE BERTH. `TryGetBerthCentre(cracker, out var berth)`, `delta = berth.Position - centre`, `target = groundGridWorldPos + delta` (E-I). Clearance is advisory: `_mapManager.FindGridsIntersecting(orbitMapId, chunk.Comp.LocalAABB.Translated(target), ref _found, approx: false, includeMap: false)` and Log.Warning naming anything that is neither the cracker nor in `_shuttle.GetAllDockedShuttles(cracker, _docked)`. Then the move, through the CE partial (§4.2):
```
_zLevels.WfMoveGridToLayer((chunk.Owner, chunk.Comp), orbitMap, target, groundGridWorldRot, offset: orbitDepth - groundDepth, depth: orbitDepth);
```
 This single re-parent fires EntParentChangedMessage -> RefreshGridZPhysics (Transit.cs:62-65, :77) and grants CEZPhysicsComponent + CEZGridFallerComponent; it also raises CEZLevelMapMoveEvent on every rider so their CurrentZLevel and ground-height caches are not left reading the ground layer (CESharedZLevelsSystem.Movement.cs:153-159). The map change runs SharedPhysicsSystem.HandleMapChange -> ClearJoints over the whole subtree (SharedPhysicsSystem.cs:184-212), which is why the partial calls RedockDocks exactly as MoveGridSetToMap does at Transit.cs:379.

## OPEN RISKS
- ReserveTiles regenerates biome terrain into ANY empty tile inside its bounds regardless of ModifiedTiles (verified at BiomeSystem.PlanetSetup.cs:94-105), so a later ReserveTiles over the hole refills it: an anchor deployed near the rim (WFGravityAnchorSystem.cs:421-435), or Smimsh on any landing over the site (ShuttleSystem.FasterThanLight.cs:1421), which is exactly what F7's chunk crash will do. F5 never calls it after the stamp, but F7 must either pre-empt this or accept a partially healed hole under the crater.
- The anchor ride-suppression set assumes extraction is the only thing that unanchors those anchors during the window. Any other cause between BeginChunkRide and EndChunkRide (an explosion, an admin VV) is silently swallowed and the anchor ends up Loose on a chunk with its pair still claimed.
- A grid parked inside the cut circle (a landed transport) is deliberately left behind. It ends up over Tile.Empty with no ground under its footprint; at depth 0 TryMapDown fails, so it neither falls nor lands. Including grids in the move would drag dock joints and CEZ networks with them.
- The hole stamp fires DecalSystem.OnTileChanged (DecalSystem.cs:165-206) over every disc tile, deleting the biome's own decals there while their ids stay in BiomeComponent.LoadedDecals. UnloadDecals later removes ids that are already gone, which is a no-op today; F5 does not add a WfForgetLoadedDecals for it.
- A rim index whose ground tile is still empty or space-like after the reserve gets no decal (TryAddDecal refuses on IsSpace, DecalSystem.cs:315), so a circle cut next to a chasm ships with a visibly broken ring. This is the accepted cost of not adding a rim tile prototype.
- The chunk in the berth will be found by IsDestinationClear (WFCrackerSystem.Lock.cs:198-234), so from extraction onwards the hull permanently reports WFCrackBlocker.Obstructed and the console hover could name it. Harmless now that PlanetCracked is returned first by GetBlockerReason, but the flag is still set.
- WFCrackBeamComponent lives on the projectors, which have no PVS override; a player watching the berth from more than net.pvs_range from the emitters on a capital hull sees no beam. Largely self-correcting because the beam starts at the projector sprite, and no test can catch it headlessly.
- The beam overlay's far-end maths is re-derived from ScalingViewport.CEZLevels.cs and Eye.GetViewMatrix and cannot be unit-tested: overlay exceptions and early-outs are swallowed into the clyde.overlay sawmill, so a wrong sign presents as 'no beam'. Verification needs a running client or the screenshot harness.
- Extraction costs three TileChangedEvents, and CESharedZLevelsSystem.OnTileChanged does one map-wide broadphase query per changed tile (Movement.cs:114-128) - roughly 1520 queries per event on a radius-22 cut, three times in consecutive ticks, plus three CE connector re-floods. Expect a visible tick spike at extraction on a real-sized circle.
- The crack_rim placeholder RSI is authored with directions: 4 while DecalOverlay only ever draws Frame0, so three quarters of the sheet is unreachable. The meta is deliberately not edited (changing directions without re-cutting the pngs would fail RSI validation).
- crack_hole.rsi and crack_ring.rsi ship unreferenced after F5 drops the rim tile and drives the growing ring from the overlay. Either F6/F8 claims them or they should be deleted; an unused RSI is not a test failure today.
- Adding MapLight to orbitComponents lights every ship parked on any crackable planet's orbit layer, not just the chunk. One line to revert, but it is a world-wide visual change made for the chunk's sake.
- Anchors pin their 3x3 footprints through ReserveFootprint and nothing releases those reservations, so two 3x3 squares inside the hole stay in ModifiedTiles after the disc is lifted. Harmless (pinned as empty) but the pin set is not exactly the disc.
- Smimsh is skipped entirely when the grid's map is the ticker's DefaultMap (FasterThanLight.cs:1406), so no F5 test asserts on Smimsh.
- Switching BuildCrackerInOrbit onto the sector-body path gives every existing F4 fixture a registered planet and an extra test map per test. The FTL range gate now has a body to measure from; no current F4 test FTLs into orbit, but a future one would see behaviour that used to be bypassed, and the extra map is pool-cleaned rather than explicitly torn down by the older call sites (the PlanetNetworkTest.cs:490-510 precedent does the same).
- F5 leaves the Cracked -> Disconnecting -> Released chain unwritten (only `wfcracker state` reaches those stages) and leaves the hull force-anchored after extraction, exactly as F4 did. Releasing the hull, the 60 s evacuation alarm and post-crash cleanup are F7's; the watchdog's drop deliberately produces no alarm today.
