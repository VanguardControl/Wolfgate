# ShipAccess

Per-person access control for purchased ships. Every ship has an owner (the buyer's account) and an allow list;
in Faction mode anyone carrying an ID card of the ship's company may also enter. While a ship is locked, only
those people can open its doors and lockers. Unlocked ships stay open to everyone, as before.

Players use the Access tab on the shuttle console: it shows the owner, mode and lock, lets the owner lock the
ship, add a humanoid standing near the console, remove people and mark them as builders (stored only for now).
A ship bought before this module existed has no owner; whoever holds its deed can claim it from the same tab.
Buying a ship registers the buyer as owner and, when `wf.shipaccess.lock_new_ships` is true (the default), locks
it at once. Doors and lockers added to a ship later get a reader that mirrors the lock.

The old console verbs keep working and map onto this: granting guest access also puts the guest on the allow
list, resetting guest access also clears the allow list, and the lock verb flips the grid's lock.

## Per-door rules

Each door can override the ship rule with `WFDoorAccessRuleComponent`, saved with the grid: Ship default,
Owner only, Chosen people (the owner plus allow-listed people ticked for that door), Code, Chosen people or
code, Public and Sealed. Every rule but Ship default applies whether or not the ship is locked, so a ruled
door keeps its reader enabled on an unlocked ship. Sealed closes and bolts the door for everyone, the owner
included; picking another rule unbolts it, and bolts that sealing added are removed again. Lockers keep the
ship rule. People dropped from the allow list are dropped from every door they were ticked on.

The Access tab shows the ship outline with each door as a node in its rule's colour (the same nav map the Ship
tab uses), a legend, and a list of the same doors; clicking either selects a door and shows its name, rule and,
for the people rules, checkboxes over the allow list. Only the owner can edit; others get a read-only view.
The diagram is built client-side from the doors the client knows about, so doors outside the client's view
range on a very large ship appear once the player has been near them.

Decisions taken while building F3.2: a Code door admits only the owner at the reader (chosen people count
only under Chosen people or code); Sealed is applied on map init as well, so a saved sealed door comes back
bolted; bolts need power, as everywhere in the game, so an unpowered sealed door is refused at the reader only
and bolts the moment it is powered; `ShipViewControl` was unsealed so the diagram reuses its hull drawing and
fit.

Entry points: `WFShipAccessComponent` (grid), `WFDoorAccessRuleComponent` (door), `WFShipAccessSystem` (shared
decision, hooked into `ShipAccessReaderSystem.HasShipAccess`), `WFShipAccessServerSystem` (purchase, lock,
allow list, door rules, console messages, verb bridge), `ShipAccessScreen` (the console tab) and
`ShipAccessDoorMapControl` (the door diagram).

Later steps add 4-digit codes and the keypad (F3.3).
