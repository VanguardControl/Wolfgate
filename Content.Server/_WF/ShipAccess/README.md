# ShipAccess

Per-person access control for purchased ships. Every ship has an owner (the buyer's account) and an allow list;
in Faction mode anyone carrying an ID card of the ship's company may also enter. While a ship is locked, only
those people can open its doors and lockers. Unlocked ships stay open to everyone, as before.

Players use the Access tab on the shuttle console: it shows the owner, mode and lock, lets the owner lock the
ship, add a humanoid standing near the console, remove people and mark them as builders (stored only for now).
A ship bought before this module existed has no owner; whoever holds its deed can claim it from the same tab.
Buying a ship registers the buyer as owner and, when `wf.shipaccess.lock_new_ships` is true (the default), locks
it at once. Doors and lockers added to a ship later get a reader that mirrors the lock.

The old console verbs keep working and map onto this: granting guest access also puts the guest on the allow
list, resetting guest access also clears the allow list, and the lock verb flips the grid's lock.

Entry points: `WFShipAccessComponent` (grid), `WFShipAccessSystem` (shared decision, hooked into
`ShipAccessReaderSystem.HasShipAccess`), `WFShipAccessServerSystem` (purchase, lock, allow list, console
messages, verb bridge) and `ShipAccessScreen` (the console tab).

Later steps add per-door rules and the door diagram (F3.2), 4-digit codes (F3.3) and outposts (F3.4).
