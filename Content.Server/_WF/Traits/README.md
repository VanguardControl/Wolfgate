# Traits

Data-driven conditions and effects for the existing character traits, ported from DeltaV's trait rework without
replacing Wolfgate's trait prototypes, editor or database rows. A trait may now list `conditions` that must hold before
it is selectable or applied, and `effects` that run when the character spawns. The old `components`, `traitGear`,
`whitelist`, `blacklist`, `cost` and category fields keep working, so every existing trait is unchanged.

Conditions cover job, department, species and component checks, each with `invert`. Effects add components, override
components, remove components, or spawn an item in the character's hand. The editor disables traits whose known
conditions fail and shows the requirement in the tooltip; the server checks them again at spawn. Existing restriction
fields are surfaced the same way: a species-, biotype-, conflict- or body-blocked trait stays listed and its popup says
why it cannot be chosen. No database migration is needed because traits are still saved by prototype ID in the
existing trait rows.

Entry points: `TraitPrototype.WF.cs` adds the two prototype fields, `TraitSystem.WF.cs` is the server hook called from
the upstream spawn loop, and `TraitsTab`/`TraitCategory`/`TraitEntry` under `Content.Client/_WF/Traits/UI` drive the
editor, with `TraitConditionUi` supplying condition checks and tooltip lines.
