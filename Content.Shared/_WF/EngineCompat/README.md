# EngineCompat

Keeps upstream content building on a newer RobustToolbox (v291) than upstream Monolith uses (v277).

- `PrototypeIdSerializers.cs`: engine v289 removed the `PrototypeId*Serializer` validators; these copies keep
  upstream `string` prototype ID fields and their YAML linter validation. Upstream files only swap their `using`
  line to `Content.Shared._WF.EngineCompat`.
- `PrototypeFlagsTypeSerializer.cs`: v289 kept `PrototypeFlags<T>` but dropped its serializer (tool qualities).
- `light_mask.yml`: a light mask for Frontier's turret beam; v291 replaced PointLight `mask` paths with
  `lightMask` prototypes. The upstream masks are in `Resources/Prototypes/light_mask.yml`, copied verbatim from
  space-wizards so a later upstream merge adds an identical file.

When upstream moves to the new engine and converts its fields to `ProtoId<T>`, delete the serializers and the
swapped `using` lines. Every other upstream file this bump touched (`IMapManager` to `SharedMapSystem`,
`[ValidatePrototypeId]` constants to `ProtoId<T>` fields, analyzer and API fixes, inverted fixture bounds) is
listed under `unmarked` in `Tools/_WF/Ci/modules.yml` with the engine change it follows.
