# FarPrediction

Steadies a player's own predicted movement on ships far from the map origin.

The client runs the stock engine, whose physics solver works in float world coordinates. Those are 2 mm apart at the
30 km sector edge and 8 mm apart in the Deep, so every predicted step of the player's character lands a little off,
the server corrects it each tick, and the view, which follows the character, shakes. Lupine fixes the solver on the
server, but the client can't be patched, so this module corrects the result from content: after each predicted physics
step it puts a predicted body where the same step lands when taken in its grid's own coordinates.

It only acts where all of these hold, and otherwise leaves the engine's answer untouched:

- the body is predicted, awake and sits on a grid (not loose in space) more than 4 km from the origin on either axis;
- nothing solid is touching it and no joint holds it, so walls and pulling behave exactly as before;
- the engine's answer is within four float gaps of the expected one (the stock solver stays within 2.4), so anything
  larger, such as a teleport or a shove, is kept.

Entry points: `WGFarPredictionSystem` (client; notes positions after every physics controller has run before the
solve and corrects them before any runs after it), `WGFarPredictionMath` (the step and the tolerance) and the
replicated cvar `wg.prediction.far_correction` (default on; set it to `false` on the server to switch every client's
corrector off live).

Not covered: movement while touching a wall or pulling something, which keeps the stock behaviour, and the client's
renderer. The renderer works in floats: it puts sprite corners into world coordinates on the CPU, and the GPU
multiplies them by the projection and view matrices before snapping to pixels. On a moving ship that shows as an
occasional pixel of shimmer from about 64 km out and 3 to 7 px of shake at 300 km (tested on the test server and in a
float32 model of that pipeline; none within 32 km). Content can't change it while clients run the stock engine.
Docs: `Docs/_WG/Engine/README.md` for the server side.
