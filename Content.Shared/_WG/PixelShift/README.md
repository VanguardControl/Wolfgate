# PixelShift

SS13-style pixel shifting. Hold **Pixel shift** (`WGPixelShift`) and tap movement keys to nudge your own sprite a pixel
at a time; hold **Tilt sprite** (`WGPixelTilt`) and tap left or right to lean it 5 degrees at a time. Holding a movement
key keeps nudging, every 0.1 s after the first 0.3 s, and the sprite glides between steps. **Reset pixel
shift and tilt** (`WGPixelShiftReset`) puts it back, and so does taking a step (a movement key pressed with neither
key held, while the mob can move; turning in place doesn't count). All three start unbound and sit under Movement on
the Controls tab. The SS13 preset puts shift on B and tilt on V; B is also Resist there, and the shift binding gets a
higher priority so both fire.

Pressing either key stops a walking mob, and it stays stopped after the key is let go until a movement key is pressed
again, like the turn-in-place key. Ghosts and anything else without a mob state ignore the keys and keep moving.

Limits are server cvars: `wg.pixel_shift_max_offset` (16 px per axis, half a tile) and `wg.pixel_shift_max_tilt`
(45 degrees). Lowering one pulls existing shifts back inside it. Restrained, stunned, critical, dead or asleep mobs
can't adjust it (`ActionBlockerSystem.CanInteract`), and holding a key still keeps them from walking.

`WGPixelShiftComponent` holds the shift and is networked, so everyone sees it. The server adds it on the first tap;
`SharedMoverController.WgTryPixelShift`, from a marked edit in `HandleDirChange`, hands key presses to
`WGPixelShiftSystem.TryNudge`, or to `ResetOnWalk` when no key is held, and key releases to `ReleaseDirection`. The
server repeats held movement keys in `WGPixelShiftSystem.Update`.

On the client `WGPixelShiftVisualsSystem` glides the shown shift and tilt toward the set ones each frame, so a nudge, a
reset or a step eases rather than snaps, and adds them to the sprite after animations run; `WGPixelShiftRestoreSystem`
takes them off before the next frame, the same pattern as Waddle, so lunges, jitter and the lying-down rotation still
play from the mob's own base. The tilt glides out while the mob is down, buckled, drawn lying (`RotationVisuals`) or
turning to or from lying, and back in once it is upright, so standing up always ends upright plus the tilt. Only the
body moves: `StatusIconOverlay` (marked edit) and the xeno HUD overlays draw from
`WGPixelShiftVisualsSystem.UnshiftedOffset`, and a marked edit in `JitteringSystem` keeps the shift out of the base
offset jitter returns to. Sprite layers such as the typing indicator still move with the body.
